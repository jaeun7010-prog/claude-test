# 진행 상황 (2026-10-22 오후) — 결제 점검, 마이페이지 정리, 이름 뜻 같은 묶음 문장

## 한 일
- **결제 설정**: `.env.local`에 `SUPABASE_SERVICE_ROLE_KEY`, `NEXT_PUBLIC_PORTONE_STORE_ID`, `NEXT_PUBLIC_PORTONE_CHANNEL_KEY`, `PORTONE_API_SECRET` 확인 (값은 보지 않음). `PORTONE_WEBHOOK_SECRET`은 로컬에서 필요 없음(배포 때 웹훅 등록). 포트원 테스트 결제로 리포트 4건 결제 완료, 결제 후 유료 내용 열림 확인(사용자).
- **결제창 가림** (`use-checkout.ts`): 우리 모달이 `<dialog>.showModal()`이라 최상위 층에 그려져 포트원 결제창을 가렸다. 결제창 직전에 모달을 닫고, 취소·실패하면 다시 열어 오류와 결제 버튼을 보여 준다 (리포트·굿즈).
- **저장 이름 삭제**: 목록의 이름별 휴지통, 체크한 이름 "선택 삭제"(`deleteSavedMany`), "정말 삭제할까요?" 확인. 주문은 남고 `history_id`만 비워진다. 비교 체크는 개수 제한 없이 고르고 비교는 2~3개일 때만.
- **중복 저장 막기** (`findSavedDuplicate`): 같은 성·이름·한자·종류·입력 조건이면 기존 상세(`?already=1`)로 보낸다. 이미 쌓인 김린하 3개는 사용자가 정리(10-17 저장분은 조건이 달라 별개).
- **리포트 구매 표시**: 최근 주문 6건 모두 저장 이름과 `history_id`로 바르게 연결돼 있었다(원인은 상세 화면이 결제 여부를 보지 않던 것). 목록 "리포트 구매" 배지, 상세·`/goods` 리포트 카드에 "리포트 보기"·"PDF 다운로드"(`/report/[id]?download=1` 바로 내려받기).
- **주문 내역** (`components/mypage/order-list.tsx`): 한 주문 한 칸(이름·한자 / 상태 배지 / 상품·금액·날짜 / 버튼). 리포트 [리포트 보기][PDF 다운로드], 굿즈 [송장 번호 복사](배송 중·완료)·[같은 이름으로 다시 주문]. 결제 대기와 결제 전 취소 주문은 숨김. 포트원 주문명(`item_name`)은 "이름핏 프리미엄 리포트 - …" 그대로.
- **이름 뜻 같은 묶음 문장** (`name-meaning.ts`의 `sameGroupPhrase`, 사용자 결정 (나)): 남궁로하(露荷)에 문장이 없던 원인은 버그가 아니라 두 글자 뜻 묶음이 같으면(맑음 + 맑음) 문장을 만들지 않던 규칙. 복성에서 이름 글자를 집는 것은 결과 카드·저장 상세·PDF 모두 정상. 남궁도훈은 渡에 문구가 없어서.
  - 예: 露荷 이슬과 연꽃처럼 맑은 · 淸露 이슬처럼 맑은 · 玹瑀 옥처럼 빛나고 맑은 · 熙星 별처럼 환히 빛나는 · 淨淸 마음이 맑은.
